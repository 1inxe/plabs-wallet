# 对发布者的影响与运营准备

0.5.2 的代码修复状态见 [修复记录](REMEDIATION-0.5.2.md)；下文列出持续的运营责任，不能把修复当作运营或法律问题已经解决。

本文件是结合代码审查与 Chrome 官方规则的风险梳理，不是针对尚未确定的经营主体、国家或地区作出的法律意见。用户将主体、联系信息设为待定，因此无法得出“在哪些地区一定可合法上线”的结论。

## 你最直接承担的五类影响

| 事项 | 实际影响 | 发布前行动 |
|---|---|---|
| 用户资金 | 签名、Gas、存款和恢复错误可能造成损失、投诉和争议；“实验功能”提示不能替代正确的后台边界 | 先修复 SECURITY-REVIEW 中 H-01/H-02；明确自己是否运营收费 Relayer/池/后端；不要承诺收益或保本 |
| 隐私承诺 | 隐私交易仍有 IP、cmx 查询、EVM Gas 与明文恢复元数据关联 | 按真实数据流发布政策；确认服务端日志字段、保留期限和用途，先修 H-03 |
| 个人身份公开 | Google 要求申报 Trader/Non-Trader；Trader 身份验证资料会公开在商店条目，包括法定名称、地址和电话 | 使用真实、适合公开的经营联系信息；不要为隐藏地址而虚假申报 Non-Trader |
| 软件更新控制 | 商店发布账号一旦失陷，恶意更新可能在用户下次解锁时取得密钥；已发布 npm SDK 也是另一条供应链 | 发布账号启用强双重验证/安全密钥，恢复码离线保存；避免长期发布 token；独立发布环境并留存制品哈希 |
| 维护与支持 | 商店要求准确联系信息和产品支持；用户卸载后仍可能存在链上交易或独立备份恢复需求 | 使用长期支持邮箱，建立漏洞响应、停发新版本与用户通知流程，文档解释 EVM 与隐私备份不同 |

官方身份规则：所有发布者需申报 Trader/Non-Trader；分类依据实际经营活动，而不是“是否个人”“是否收费”一个条件。Trader 的地址和电话等信息将显示在条目中。见 https://developer.chrome.com/docs/webstore/program-policies/trader-verification-faq 。

Google 协议要求你具备发布权利、遵守适用规则、维护支持联系方式；违反政策可能导致移除或停用产品。谷歌审核通过不等于合约安全认证，也不取代适用法律义务。见 https://developer.chrome.com/docs/webstore/program-policies/terms 。

## 个人还是公司

当前不能替你选定法律主体。若项目长期运营并收取手续费，应先核对商标、域名、代码与合作方的归属、收费关系、经营地区和税务事项。公司主体有助于明确运营身份和支持渠道，但不自动免除个人不当行为或其他法定义务；不能承诺“注册公司就不承担责任”。

若用个人名义发布，需接受相关商店公开信息及长期维护职责。实际填写前检查后台公开预览，避免误公开私人家庭联系方式，同时不得提供虚假地址。

## 应交给当地专业顾问确认的具体问题

- 经营主体所在地、用户目标地区，以及是否向这些地区推广隐私交易服务。
- 是否控制/升级资产池、Relayer、手续费接收地址或协议治理；是否收手续费、托管或代用户执行资产操作。
- 自托管软件发布与运营链上服务在适用地区的区别，是否存在许可、制裁、反洗钱、消费者保护、数据保护或税务要求。
- 境外 RPC/Indexer/Relayer 的数据传输和服务合同；哪些主体决定日志用途和保存期限。
- 预编译引擎、电路、字体和设计资源的许可与商标授权。

本次未审查后端、协议运营主体或司法辖区，因此不作“无需任何资质”或“全球可用”的承诺。不要照搬 Google Play 的金融应用要求当成 Chrome Web Store 的同一套规则。

## 最小运营方案

1. **发布物管理**：维护源代码版本库与受控分支；每次保存锁文件、源码快照、依赖清单、ZIP SHA-256、商店版本和变更记录。当前目录没有 Git 仓库，可先以证据快照追溯，不能宣称可复现构建已完成。
2. **更新安全**：升级构建工具后分清开发依赖与运行制品；对 vendored binaries 单独核验来源/签名。保持 store extension ID 稳定，避免用户误装同名新钱包；迁移前强提醒备份。
3. **支持规则**：客服只收集版本、链、时间、错误码和必要的交易 hash；提醒 hash/地址可关联身份。绝不索要助记词、私钥、Vault 密码、Seed。导出的加密 Vault 也不应常规上传给客服。
4. **安全事件**：记录受影响版本与发生时间；暂停新推广/后续发布，先判断是否与已广播交易有关；通过正式渠道通知，保留最少必要证据。不能依赖商店下架撤回既有交易，也没有已经验证的远程杀开关。
5. **恢复说明**：强调 EVM 恢复材料与独立隐私 Vault 均需备份。修改密码不能撤销泄露的旧备份；真正密钥失陷可能需要迁移到新账户，不能简单告诉用户“改密码就安全”。
6. **费用边界**：原生 Gas 与隐私手续费逐笔披露，网络确认可能失败且费用不可退；1 个原生币的代码上限跨网络价值差异很大，不能当作统一的小额风控。
7. **数据请求**：建立本地数据删除与后端日志请求的说明，区块链不可删的部分单列；给所有待定字段安排责任人和确认日期。

## 建议的发布路径

先修高优先级交易/隐私问题 → 补供应链/合约审计与运营资料 → 取得当前真实截图和可访问政策/审核站点 → 建立可追溯的新制品 → 受限分发 → 逐步扩大发布。

用户本轮要求不运行自动测试，相关资金与并发场景仍标为未验证。若后续决定验证，应使用隔离的无真实资产环境，单独设计安全边界案例；不能拿当前真实钱包做审计实验。

# 0.5.4：明确失败与未知结果分类

- 新原生交易仅在收到匹配请求 ID、合法 JSON-RPC error，且节点消息严格匹配余额不足时认定该发送被拒绝。已构造的本地 hash 不等于节点已接受；被拒绝 attempt 不再占据 pending hash 列表。
- 拒绝发生前若有其他未确认的授权交易，继续保持核对；不会因最后一步余额不足而丢弃此前提交。
- 本地广播前校验/签名失败保持 failed-before-broadcast；节点明确余额不足同样归入未接受的失败记录，不再阻塞新意图。
- 旧记录解锁时检查同账户的全部 journal，包括 0.5.2 已加密迁移的旧错误。仅当存在明确余额不足证据且没有 hash、发送 attempts 或 Relayer 编号等相反证据时更正，并同步活动历史。无证据不会仅凭用户截图批量改状态。
- timeout、nonce too low、already known、replacement、一般服务器错误均不算明确拒绝。存在 hash 却查询不到回执仍不证明失败。
- 操作记录仍保存，不删除历史，也不自动补 Gas 或重发交易。

迁移在扩展重新加载后的隐私会话恢复或用户解锁时执行。旧版本若已丢失原始错误，则可能仍需专门核对。本轮没有读取真实钱包记录，所以不保证截图中的两条一定满足自动修正规则。

验证：TypeScript/Vite 构建与制品检查；遵照用户要求未运行自动测试、UI 回归、签名或真实交易。版本 0.5.4。

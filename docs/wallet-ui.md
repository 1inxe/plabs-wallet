# Wallet interface

PLabs is primarily a privacy wallet. Default to private assets and their total USD estimate (displayed with the `$` prefix); public ERC-20 assets belong in a secondary tab. Keep private transfers, receiving, shielding and NFT ownership prominent. Use `#14bb87` as the primary accent, charcoal surfaces with clear tonal separation, and concise copy. Buttons, selected navigation, focus states and progress bars share the same accent.

Asset sync is a borderless status line on the assets page and part of the title section on the collectibles page. Keep the privacy state, token/NFT sync phase and percentage on one line, with a 2px progress track below. Do not enclose it in a card, add a tinted background, or show raw block numbers by default. Clicking the phase/percentage expands scan details without starting another sync. Hide progress and collapse details when the operation ends. Keep the lock and retry actions independent.

Show both token quantity with its unit and the estimated USD value, plus 24-hour price changes. Aggregate portfolio changes using the current quantities at current and previous prices; this is a market-value comparison, not realized profit. Missing quotes default to $0.00 and 0.00%, with a compact indication of incomplete pricing. Use `$7.00`, `+$0.39` and `-$0.39` for fiat values; retain token symbols for quantities such as `7 sUSDC` or `0.0116 ETH`. Do not use a literal U suffix. Fiat amounts use two decimal places; changes rounding to zero have no negative sign. Locked or explicitly hidden balances remain masked.

Prices come from DefiLlama's current-price and percentage APIs. Canonical contracts, never token symbols, determine identity. Private assets inherit their configured underlying asset's quote with the pool's scale/decimal conversion. P20 has no assumed dollar peg. Pricing requests contain only public token identifiers, with no account addresses, balances or private notes. Quote fetching belongs in the trusted extension background, with bounded responses, timeouts and caching.

Chrome toolbar popups choose their own initial viewport. Use the preferred 370px width consistently for the wallet, bottom navigation and approval windows. Set an explicit 370px width for `html.wallet-popup`; do not constrain that width with `100vw`, which can trap the popup at its tiny initial width. Verify a real toolbar popup with `viewport: null` in addition to regular browser fixtures.

The wallet supports Simplified Chinese (default) and English under Settings → Language. UI preferences use `walletUiLanguage` in Chrome local storage, with a local first-paint cache and cross-window updates. Use `t()` from `src/i18n` for wallet copy and add English entries to `en.json`. Keep account names, token symbols, addresses, recovery phrases and signed messages in their original form. Language changes must preserve form inputs, proof jobs and transaction state. The root subscribes with `useLanguage()` so a language change rerenders the existing tree without changing component keys.

Bottom navigation is an icon-only floating glass surface, 334px wide inside the 370px popup, inset 18px from the left and 12px from the bottom. Keep accessible labels and hover names. Selection and hover are painted by an absolutely positioned pseudo-element; they must not change padding, borders, font weight, icon size or grid tracks. Never size a fixed footer with `width: 100%`: a native vertical scrollbar changes its containing width by 4px and moves every icon when switching between long and short pages. Reserve a stable scrollbar gutter and reset page scrolling in a layout effect, before painting. Test actual toolbar popups at device scale 2 as well as regular browser fixtures, including pointer clicks from the bottom of long pages.

The unified activity list also reads NFT sends from the current privacy account's encrypted NFT journal, including records made before NFT activity support. These records remain visible after the spent NFT leaves the holdings grid. Show the collection and `#tokenId`; the ID is never a fungible amount. Listen for NFT journal changes and refresh pending sends through the read-only status path, without signing or rebroadcasting. Keep the existing fungible SDK history response separate until its public schema supports NFTs.
